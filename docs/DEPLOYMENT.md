# Deployment: one service, one database

You need only two accounts: **MongoDB Atlas** (database) and **Render** (hosts the whole app). The web app and API run as one service, so there is no CORS, no second host and no email service.

## Free-tier facts (checked October 2026; terms change, re-check)
- **Render free web service:** sleeps after 15 minutes without traffic (about a minute to wake); the disk is temporary, which is why evidence files are stored in the database; Render's own docs say not to use Free instances for production. A paid instance (about $7/month) removes the sleep.
- **Atlas M0 free cluster:** 512 MB shared by records and uploaded files; sources I found say no automated backups on the free tier. Confirm on Atlas's limits page.
- Anything that holds real student data should run on paid tiers with backups.

## 1. Database (Atlas)
1. Create a free cluster. Under **Database & Network Access → Database Users**, add a user (autogenerated password, letters and numbers only) with **readWrite** on the `nmamit_portal` database.
2. Under **IP Access List**, allow `0.0.0.0/0` (Render's free tier has no fixed IPs). Safety then rests on the database password, so keep it long and private.
3. **Connect → Drivers**, copy the string, put the password in, and add `nmamit_portal` before the `?`:
   `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/nmamit_portal?retryWrites=true&w=majority`
   *If your computer cannot resolve `mongodb+srv` (error `querySrv ECONNREFUSED`), use the **Legacy URI String** toggle instead.*

## 2. Put the code on GitHub
```bash
git init && git add . && git commit -m "NMAMIT Mentor-Mentee Portal"
git remote add origin https://github.com/YOU/nmamit-portal.git && git push -u origin main
```
Run `git status` first and confirm no `.env` file is listed (it is git-ignored).

## 3. Render
1. **New → Blueprint** → choose the repo (it reads `render.yaml`). Render asks for `MONGODB_URI`: paste the Atlas string.
2. Deploy. `SESSION_SECRET` and `HOD_ACCESS_CODE` are generated for you. Departments and the syllabus load on first start.
3. Open `https://YOUR-SERVICE.onrender.com/api/health` and expect `{"ok":true}`, then open the site root.
4. **Give each HOD the access code** (Render dashboard → your service → **Environment** → `HOD_ACCESS_CODE`, or set your own 8+ character value). Share it privately. Each HOD then uses **HOD sign up**; a branch can have only one active HOD.
(Prefer Docker? The `Dockerfile` builds the same single image.)

## 3b. Optional: web app on Vercel, API on Render
Render still runs the API and the database connection. Vercel serves the React app from its CDN and forwards `/api/*` to Render. The browser only ever sees the Vercel domain, so session cookies and the rest of the code stay unchanged.
1. In `client/vercel.json`, replace `nmamit-mentor-mentee-portal.onrender.com` with your real Render hostname (shown at the top of the Render service page). Commit and push.
2. Vercel → **Add New → Project** → import the repo. Set **Root Directory** to `client`. Framework preset: Vite. Deploy. No environment variables are needed.
3. Open `https://YOUR-APP.vercel.app/api/health` and expect `{"ok":true}`, then open the site root and log in.
4. Keep `TRUST_PROXY_HOPS` checked: all users may share one rate-limit bucket behind two proxies. After deploying, log in from two different networks and confirm one user's failures do not lock out the other. If they do, change `TRUST_PROXY_HOPS` on Render to `2`.
5. Uploads: Vercel may cap request bodies below the 5 MB evidence limit. Test a 4 MB and a 5 MB file after deploying.

Both hosts are on free tiers. Expect the Render free service to wake slowly (see above).

## 4. Operator tasks (rare)
Run from your own computer with `server/.env` pointing at Atlas:
```bash
cd server
npm run admin -- reset-password --email hod@nmamit.in      # a HOD forgot their password: prints a temporary password
npm run admin -- set-status --email hod@nmamit.in --status suspended   # free a branch for a new HOD, or lock an account
```
Students and faculty never need the operator: their HOD uses **People & passwords** to issue a temporary password.

## 5. Check the live site
1. HOD sign up (use the code) → dashboard. 2. Faculty sign up → shows "waiting for approval" → HOD approves under **Faculty approvals** → faculty logs in. 3. Student sign up with the branch and first-year group → **Academic portfolio → Add semester subjects**. 4. Faculty → **Find mentees** shows only that branch's students → add one. 5. Student enters marks (MSE 21 must be refused) → submit → faculty verifies → HOD endorses. 6. HOD issues a temporary password → the student must choose a new one. 7. Download the Excel export.

## Troubleshooting
| Symptom | Likely cause |
|---|---|
| First load takes a minute | Free Render service waking |
| Server exits at start mentioning `SESSION_SECRET` | Missing or under 32 characters |
| "HOD registration is not enabled" | `HOD_ACCESS_CODE` is empty |
| Mongo timeout | Atlas IP list, or special characters in the password |
| `querySrv ECONNREFUSED` | Use the legacy (non-SRV) connection string |
| Everyone rate-limited together | `TRUST_PROXY_HOPS` should be `1` on Render |
| Uploads vanish after a restart | `STORAGE_DRIVER` is `disk`; use `mongo` |
